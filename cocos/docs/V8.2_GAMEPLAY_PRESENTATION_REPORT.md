## 2. Arena 收集失败的根因（本轮最重要的结论）

### 2.1 A/B/C/D 分类过程与证据

| 分类 | 判定 | 证据 |
|---|---|---|
| CASE A 导航 | **成立过，已修** | 摇杆标定实测：摇杆 dy 与世界 Z **同号**，而驾驶员写了 `- dz`（垂直轴取反），所以它一边移动 30–62m 一边朝目标反方向走。修正后固定点收敛实测 **0.28m / 0.30m**，驾驶员洗清 |
| CASE B 吸附未激活 | 未成立 | 物体能进入 ATTRACTED→SUCKING→ABSORBED |
| CASE C 坐标错配 | **不成立** | 本地竞争者 `node` 与玩家 `machine.node` 是同一引用；产品距离公式 `distanceXZ` 被直接复用，未在测试里重写 |
| CASE D 候选过滤 | **成立** | `OWNED_BY_BOT`（episode 级 3/3）；产品自身 trace 给出命名拒绝原因 |

### 2.2 修复的四个代码缺陷（每个都有实测前后对照）

| # | 缺陷 | 实测效果 |
|---|---|---|
| ① | Bot 节流 `continue` **丢掉整个物体**，而不是让给下一个空闲竞争者 | episode 进入吸附半径 0/3 → **4/4** |
| ② | 选择器与执行器不一致：owner 够不到物体时，选择器把物体交给别人，`updateMotion` 因陈旧归属当场拒绝 → **物体永久冻结** | episode 0/6 → **10/10 完整走完 FSM** |
| ③ | 预热期（战斗禁用）Bot 仍追猎无法自卫的玩家 | 解锁即死 5/5 → **2/5** |
| ④ | **竞技场从不运行收集品生命周期**：Endless 在 `updateObjects` 里移除被吸收物体并释放槽位重生，Arena 只 `continue` 跳过 → 物体永久滞留、槽位永不释放、**资源单调枯竭** | 玩家周边 12m 的 T1：开局 23 → 8.5s 后 0 → **永不恢复**；修复后收集 0→10-17/局 |

**④ 是根因。** 修复方式：`InfiniteWorldCell.removeAbsorbedCollectibles` + `InfiniteWorldManager.maintainCollectibleLifecycle(dt)`，Arena 分支调用；**刻意不调 `updateObjects`**，否则会把 Endless 吸附也跑一遍、双重驱动物体（§15）。

## 4. 击杀链（§12）

### 4.1 缺失的是「Chase」这一步

基线报 0 击杀机会，但数据显示玩家曾达到质量 **10690** 而最近对手仅 **242**（44 倍差距）——仍被计为 0 威胁。原因是 `localKillableIds` 要求**距离 ≤ 4.8m**，而**诊断驾驶员只会收集、从不追击**；更弱的 Bot 会逃跑（FLEE），更强的追不上，所以可击杀状态永不触发。

给驾驶员加上追击（按与战斗规则相同的质量谓词 `localMass >= mass*1.32` 选择目标）后：

| 局 | 首次可击杀 | 首次击杀 | rank |
|---|---|---|---|
| 1 | 18.9s | **19.6s** | 7 |
| 3 | 20.2s | **21.0s** | 4 |

10 局运行：**5 局发生真实击杀**，首次可击杀 17.8–19.5s，首次击杀 18.5–20.3s。

### 4.2 真实击杀时间线（§25 验证）

| 局 | 首次可击杀 | 首次击杀 | HUD 反馈 |
|---|---|---|---|
| 3 | 19.5s | 20.3s | **`淘汰 蓝莓 +177`** |
| 7 | 17.8s | 18.5s | **`淘汰 雪球 +165`** |
| 8 | 19.4s | 20.2s | **`淘汰 蓝莓 +154`** |

击杀反馈：`ArenaMatchManager.defeat()` 在击杀者为本地玩家时发 `ARENA_LOCAL_KILL`（对手名／掉落质量／位置），`ArenaHUDController` 订阅后经**已有的浮动反馈池**显示 1.1 秒金色文本，**无模态、无暂停、无新 update 循环**。

**已知局限**：5 次击杀中有 2 次未采到反馈文本，与既有 presenter 的视口守卫一致（投影位置落在安全边距外时不显示）。屏幕边缘的击杀不显示反馈——值得跟进，但不是本路径的正确性缺陷。

### 4.3 可击杀可读性（§24）

三种状态全部来自**同一战斗谓词**（`localKillableIds` 与 `localThreatIds` 互为角色互换）：

| 状态 | 表现 |
|---|---|
| DANGER | 红色 `危险 <名>`（字号最大，最不可漏） |
| KILLABLE | 轻黄绿 `可追 <名>` |
| NEUTRAL | 白色 `<名>` |

实测：同一局内同时出现 `危险 矿石` 与 `可追 蓝莓`，且该局发生了真实击杀。

## 6. Player Visibility（§26）

**部分完成，未通过。**

新增插桩 `playerVisibility`（玩家屏幕归一化坐标 + **黑洞核心在屏半径**，经真实 gameplay 相机与机器自身吸附半径测得，非重写几何）。

| 模式 / 等级 | 采样帧 | 在屏半径 | screenX | screenY |
|---|---|---|---|---|
| Endless LV1 | 28 | **92–93 px** | 0.46–0.53 | 0.38–0.40 |
| Endless LV2 | 36 | **93–94 px** | 0.47–0.53 | 0.38–0.40 |
| Arena LV1 | 107 | **48–49 px** | 0.48–0.52 | 0.42–0.43 |

**出屏采样 0 次**，屏半径 < 20px 采样 0 次。两种模式下玩家始终居中且核心清晰可辨。

**LV3/LV5 无法验证，原因是一个独立的发现**：进化阈值为 LV2=900、LV3=15000、LV4=55000、**LV5=180000**。实测竞技场 90 秒峰值质量 10900（LV2），Endless 150 秒到 2625（LV2）。也就是说 **LV3 及以上在正常单局中基本不可达**，LV5 需要 180000 质量。这属于成长节奏的设计问题，不是可见性缺陷，但意味着玩家几乎看不到 LV3–LV5 的机器装配。

**PLAYER_VISIBILITY_PASS 不予声称**——LV3/LV5 未采，且遮挡（occlusion）尚无程序化判定，只有像素复核。

## 9. 已知问题与剩余风险

1. **击杀反馈的视口守卫**：屏幕边缘的击杀不显示反馈文本（5 次击杀中 2 次未采到）。
2. **PLAYER_VISIBILITY 未完成**：需玩家屏幕边界/遮挡插桩 + LV3/LV5 复核。
3. **Arena 完整切片未一次性录制**：各环节都已单独验证，但缺一条从 Start 到 Settlement 的连续证据。
4. **arena 20 局平衡基线的击杀机会率**：修复后 10 局运行中为 5/10（首次可击杀 17.8–19.5s）。按 §21 属于"玩家能稳定成长且存在击杀机会"，未再标 BALANCE_FAIL，但样本仍偏小。
5. **诊断驾驶员仍是我的代码**：本轮它自身已产生 5 个采集缺陷（摇杆触摸起点、`tier<=3` 硬编码、缺 `consumed` 断言、追已占用物体、垂直轴取反）。**任何速率类结论都应先怀疑驾驶员。**
6. **本轮有 3 次平衡猜测被实测否定并回退**（永久归属、强制 owner、预热降速）——每次都讲得通，但都没推动指标。
