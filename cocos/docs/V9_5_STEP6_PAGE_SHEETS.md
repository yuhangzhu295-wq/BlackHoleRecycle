## 结论

**8 张并排图逐张人工看过：三尺寸下均无裁切、无遮挡、无缺图、无错位。** 换皮后的美术在三种屏宽比下构图一致，文字与按钮都完整可读。

### 两次「疑似缺陷」——查证后均为误判（记录过程，因为这是本步骤最容易出错的地方）

1. **机器档案的缎带「被卡片切掉」。** 缩略图上看缎带两端像被卡片内边缘截断。
   - 运行时几何实测：`MachineCard` 宽 542.9 设计单位，`MachineRibbon` 宽 500 → **窄 42.9，比例 0.921**，两侧各留 21.5 设计单位（390 宽下 ≈ 26 屏幕 px）。
   - 像素扫描（`machine-390x844.png` y=96）：`暗18 | 青边框6 | 白7 | 过渡4 | 缎带319 | 过渡4 | 白6 | 青6 | 暗18` ⇒ 缎带两侧确有白边，**没有贴边、没有裁切**。
   - ⇒ **误判**。缩略图（0.6× 缩放）不足以判断贴边。
2. **复活页状态行「顶到卡片边缘」。** 375×667 下这行 `被 风暴 吞噬 · 对方 2590 / 你 240 · 已击败 0 名对手` 几乎占满卡片内宽。
   - 3× 放大后目视：左侧留白 ≈17 px、右侧 ≈29 px，**文字完整在卡片内**。
   - ⇒ **误判**（但确实偏紧，见下）。

> 教训与既有门禁一致：**几何门禁只问「有没有超出屏幕边框」，问不到「有没有超出自己的父卡片」**。而目视缩略图又会把「留白偏紧」看成「被切掉」。两者都要用，且都要量化。

### 记录但不作修改的构图观察（非缺陷）

| 观察 | 说明 |
| --- | --- |
| 模式选择 / 结算在 430×932 下下半屏大片留白 | 布局表按固定设计高度钉死并居中，高屏比下必然留白。**改它就要动已钉死的布局契约**（`test_mode_select_layout_contract` / `test_settlement_layout_contract`），属设计决定，不在本轮范围 |
| 复活页状态行在 375×667 下左右留白偏紧（≈17 px） | 文案最长的一行，最窄屏下接近满宽。若后续文案再变长会溢出，**建议给该 Label 加宽度上限或换行策略**（未改，需先确认设计意图） |
| 结算数值全为 `0 件 / 0 kg / +0` | 采集路径是「开始 → 暂停 → 结束并结算」，本局没有实际吞吐，属采集方式使然，不是缺陷 |
