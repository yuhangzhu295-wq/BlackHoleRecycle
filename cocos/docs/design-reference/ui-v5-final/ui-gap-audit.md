# UI Gap Audit — v5 reference vs current runtime

Round 1. **Audit only — nothing was changed to make this document true.**

- Baseline HEAD: `ee11d68bb9e6dff4149f6475ef22694e5161afd8`
- Reference: 《黑洞回收站 UI方案包》2026-09-28 (see `design-manifest.json` for the file list and hashes)
- Runtime evidence: `artifacts/qa/portrait/portrait-390x844-*.png` (git-ignored, regenerated by `npm run acceptance:v2`)
- Main size under audit: 390×844; the acceptance chain also covers 375×667 and 430×932

## Coverage — read this before trusting the table

**4 of 11 reference images were reviewed directly** (mode select, endless ready, arena
gameplay, arena settlement) against their runtime screenshots. The other 7 are listed in
the manifest as `reviewed: false`. Two of them are duplicates/variants of pages already
reviewed (a second mode-select rendering, a second arena HUD), and four are theme
gameplay images that **map to no page in the current product flow**. That mapping is an
open owner decision, not something this audit can settle.

So the P0/P1 lists below are complete for the four reviewed pages and **not yet complete**
for the rest.

## A note on the package's own problem list

`02_方案文档/01_当前问题与修复方案.md` opens with a "current problems" section. **Part of
it is already obsolete.** It says mode selection starts the game on a single tap and that
the product lacks a Ready page and a settlement return path. Those are implemented and
guarded: `scripts/test_mode_ready_flow_contract.mjs` asserts the Ready step in source, and
the `ui-full-flow` acceptance scope drives the real runtime through
`HOME → MODE SELECT → READY → PLAYING → PAUSE/RESUME → HOME → ARENA → REVIVE → SETTLEMENT → HOME`.

The package's durable value is therefore its **visual language**, not its bug list. The
audit below is written against the images, not against that document.

## P0 — business-breaking

**None observed.** All 16 acceptance scopes pass on this HEAD, `ui-full-flow` completes the
full touch route, and every page under audit is reachable by real touch. There is no dead
button, no unreachable settlement and no state error in the evidence.

This is the load-bearing finding of the round: the remaining work is visual construction,
not firefighting.

## P1 — clearly wrong versus the reference

1. **`ModeSelectPage` renders three empty white sprite bars.** Located in
   `ModeSelectPageController.MODE_SELECT_LAYOUT`: `Header` (500×116 at y 534),
   `ShelfArena` (600×52 at y 418) and `ShelfEndless` (600×52 at y 54). In the reference
   there is no white bar anywhere on this page — the title block sits directly on the sky
   and the cards sit directly on the background. Class: `DUPLICATE_HEADER` /
   `WRONG_SPRITE`. The repository has already fought this class twice
   (`37f766a` "hide stale Header sprite in ready pages", `5954221` "clear stale
   ArenaAvailabilityLabel and EndlessBestCaption text"), so this is a regression of a
   known family, not a new idea.
2. **`ModeSelectPage` cards carry no bespoke illustration and no CTA.** The reference puts
   a full isometric city vignette inside each card plus a thick yellow capsule
   (`开始竞技` / `开始探索`). The runtime card 1 is a flat road texture and card 2 is a dark
   gradient with a small planet; the CTA degrades to a small blue pill
   (`1v7 本地竞技 · 已开放` / `最高分`). Class: `WRONG_SPRITE` + missing affordance.
3. **`ModeSelectPage` leaves the bottom third of the frame empty.** The reference balances
   the two cards across the full portrait frame. Class: `ANCHOR_DRIFT`.
4. **`ArenaHUD` is collided by a large dark structure at the top of the frame.** A dark
   building slab sits behind the `黑洞回收站` title, the left leaderboard panel and the
   centre match clock, so three separate HUD elements read against a dark, busy backdrop.
   The reference puts the title, clock and pause on clear sky. Class: `HUD_OCCUPANCY` +
   large-environment-object occlusion.
5. **`ArenaHUD` opponents are far weaker than the reference.** The reference shows each
   rival as a distinctly coloured black hole with a coloured ring, a name tag and a
   coloured arrow. The runtime shows small colour blocks and cars with floating text.
   Class: `WRONG_SPRITE` + reduced readability of "who is a competitor".
6. **`ArenaHUD` `安全准备 15s` renders as bare text** with no pill behind it, where the
   reference uses a dark pill with a clock glyph. Class: `WRONG_SPRITE`.
7. **`EndlessHUD` and `ArenaHUD` both show a large black multi-lobed blob at the bottom
   centre.** It is unidentified from the screenshot. It must be classified as Art vs World
   populate vs Cell lifecycle **before** anyone touches it — see the classification rule
   below. Class: `UNCLASSIFIED`.
8. **`HomePage` primary action does not match the reference button language.**
   `开始吞噬` renders as a thin orange outline bar; the reference language is a thick
   yellow capsule with white outline and drop shadow. The coin pill also uses a `¥` glyph
   where the reference shows a coin icon. Class: `WRONG_SPRITE` / `WRONG_LABEL`.

## P2 — spacing, type, decoration

- Title decoration: the reference titles carry a planet glyph and sparkle marks; the
  runtime titles are plain text.
- Button outline/shadow depth and capsule corner radius differ from the reference.
- Card corner radius and internal padding.
- Stat-card framing: the reference frames every stat in a deep-blue rounded card.
- Badge colours and the medal hierarchy on settlement.

## Gameplay visual issues (Phase 4 scope)

- **Unidentified black multi-lobed blob** at bottom centre in both endless and arena.
  Highest-value unknown in this round.
- **Large dark structure occluding the HUD** in arena and endless (same object family as
  P1-4).
- **Scene reads dark and road-dominant.** The reference is a bright, high-saturation
  isometric city; the runtime is grey asphalt with muted greens. This is the single
  largest visual distance between reference and product.
- **T1–T5 tier hierarchy and "edible vs pure environment" legibility** — the package's
  own request, and it is a legitimate one. Needs a dedicated instrument, not an eyeball.
- **Empty bottom region / world density distribution** in the opening cell.

### Classification rule (do not violate)

Every gameplay-visual finding above must be assigned to exactly one of **UI problem**,
**World populate problem**, **Cell lifecycle problem** or **Art problem** before a fix is
attempted. A world-logic bug fixed as a UI problem will reappear.

## Open items that are not defects

- `ModeSelectPage` card height: `describe()` reports 610×202 while `MODE_SELECT_LAYOUT`
  declares 610×278. The snapshot was taken with the page `active: false`, so 202 is most
  likely the scene-authored value and the controller applies 278 at runtime. **Not
  confirmed either way** — measure once with the page active before calling it drift.
- Two mode-select references and two arena HUD references exist in the package. Which is
  authoritative is an owner decision.
- Four theme images (街区挑战 / 庭院大冒险 / 垃圾大作战 / 街头大收集) map to no page in the
  current flow. Style reference or new level entries — owner decision.

## What is already correct

For balance: the Home page, the full page-to-page routing, the pause/resume/settlement
chain, the revive flow and the settlement information hierarchy all exist and work. The
gap is the visual language and the scene composition, not the product structure.
